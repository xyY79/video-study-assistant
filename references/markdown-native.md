# Markdown-native V2.1：单文件学习材料规范

以用户认可的《如何锻炼长时间专注力》精编版的结构为标准，而不是固定章节数、图表数、字数或压缩率。只生成一个面向阅读的 .md；UTF-8、无外部依赖、Obsidian 不需社区插件。普通 Markdown 阅读器即使不能渲染 Callout/Mermaid，仍应看到完整意义。禁止 HTML 标签、CSS、JS、iframe、外链图片、本地图片、附件嵌入、Dataview 及其他插件脚本。可以保留来源普通超链接，但不得依赖链接才读懂正文。

## 六层交付结构

1. YAML Frontmatter：title、真实课次（如有）、source_bvid 或来源、duration（可知时）、type、少量主题 tags。仅一组，字段必须真实，不猜测。
2. 唯一 H1；紧随简短 `[!abstract]` 导读与来源/阅读说明。导读不是正文替代品。
3. H2 主题章、必要 H3 子主题；按讲者论证逻辑整理、可合并跨段重复，时间区间置于章节标题后（如 `*原视频 03:32–09:51*`），不在每句话前保留时间戳。原稿没有时间时不虚构。正文以自然段为主，每段表达一个完整论点，建议 80–220 个中文字符，必要时允许更长；避免短碎句、文字墙和连续机械列表。
4. 在解释复杂关系时使用原生知识可视化：分类/条件/对比用 Markdown 表格，因果/流程/层级用简洁 Mermaid fenced code（优先 flowchart TD/LR），每张图附一句人能直接阅读的关系解释；适量 `**加粗**`、`> [!important]`、`> [!note]`、`> [!warning]`、`> [!quote]`，意译必须标注，禁止伪造引文。短文无需强制使用全部元素，不为了视觉效果把全文切成卡片。
5. 长篇课程默认在同一文件末尾提供知识结构与复习辅助：主题关系总览、问题→对应章节速查、可执行的任务清单、主动回忆问题。辅助内容必须来自正文或明确标记为编辑整理，不能变成另一本泛化教程。
6. 最后集中说明证据边界及校勘：原稿错词、高置信修正、待核实术语、时间定位与处理方式。区分讲者经验/假设/未经核实主张与编辑建议。未经回听不得声称逐字准确。仅有来源明确的事实方可表述为核实事实。

## 原创微型示例（仅示范编辑结构，非真实课程原话）

原始转录：

> （00:00:00）就是说这个任务吧
> （00:00:02）你要一直做那个就是一直做
> （00:00:04）然后不是说不休息
> （00:00:06）你休息完了再回来继续做

正确精编（示意）：

> [!abstract] 核心观点
> 持续投入不等于完全不中断，关键在于中断后的恢复。

### 持续性与恢复能力

*原视频 00:00–00:06*

持续投入并不要求完全不休息。讲者强调，任务可以在必要的休息之后继续推进，重要的是能否恢复到原先的工作状态。

| 状态 | 应对方式 |
|---|---|
| 持续工作 | 聚焦当前任务 |
| 必要休息 | 休息结束后返回任务 |

```mermaid
flowchart LR
    A[持续工作] --> B[必要休息]
    B --> C[恢复原任务]
```

工作与必要休息交替，结束休息后重新进入原任务。图不增加原文未支持的因果结论。

**复习问题（编辑整理）：** 为什么中断并不一定意味着任务的连续性被破坏？

错误做法：原始碎片逐行补句号、保留数百时间戳；只写核心观点后附上未经处理的完整底稿；用表格罗列整个口播而没有自然段；将讲者的经验包装成科学定律；为了保留 Markdown 外观而输出嵌套 HTML 或图片附件。

## 完成标准

先通过 check_lecture.py 的结构检查，再完成逐块信息覆盖和独立语义审查。数字指标仅用于发现底稿、异常碎片和格式错误，不能自动保证知识完整性；严禁凭字数保留率或标题数量宣布完成。以实际完整讲稿能否直接阅读为准。用户认可的示例应作为编辑质量基准，不将用户课程内容上传到公开代码仓库。
